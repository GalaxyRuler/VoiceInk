# Windows Context Action Guidance Design

## Context

VoiceInk for Windows already gathers enhancement context from local, user-controlled sources: active app/window details, sanitized browser URLs, selected text through UI Automation with clipboard fallback, optional clipboard context, and optional local screen OCR. The Enhancement page also has readiness rows that summarize each source.

Windows context APIs are best-effort: UI Automation text selection depends on provider support, and OCR depends on local Windows OCR/display capture availability. The UI should therefore make graceful degradation obvious and provide next actions without implying that every app will expose every context source.

## Goal

Add presenter-backed action guidance to the Enhancement context section so users can see what to do next:

- enable Enhancement before expecting context to be appended to prompts;
- enable Clipboard Context when clipboard text should be included;
- select an OCR region when constrained OCR is enabled but missing bounds;
- understand the source ordering used in enhancement prompts.

## Non-Goals

- No new OS permissions or machine-wide changes.
- No new context capture backend.
- No automatic clipboard reads outside enhancement prompt construction.
- No cloud OCR or telemetry.

## UX

The Enhancement context section shows a second compact list below the readiness rows. Each row has a title, value, detail, and badge. Rows are recalculated from `AppSettings` whenever settings are loaded or saved.

## Testability

The guidance is generated by `EnhancementContextReadinessPresenter`, so behavior is testable without UI automation.
